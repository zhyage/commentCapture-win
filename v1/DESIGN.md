## 2. 三工具职责与数据流

```
工具2 (搜索/获取URL)            工具1 (原始数据收集)           工具3 (数据分析)
 描述性条件 ──► 找到视频URL ──► 采集原始数据 ──► 分析需求 ──► 分析结果+诚实边界
 (时间/热度/主题/机构)          (评论/字幕/视频/画像/视觉)     (通用, 不绑定研究)
```

三个工具**各自独立可运行**:
- 工具1 可单独用: 给你 URL 就采(已实现)
- 工具2 可单独用: 只负责"找到符合条件的 URL 清单"
- 工具3 可单独用: 给定已采集的数据目录 + 分析需求, 做分析
- 联合使用: 2→1→3 流水线(可选)

## 6. Skill 体系 (两层, 2026-08-29)

**使用场景**: 用户 → agent → CLI。用户在**任意项目**里给出研究文档, agent 通过 skill 驱动本工程的工具。

| 层级 | 文件 | 职责 |
|---|---|---|
| **编排级** | `v1/SKILL.md` | 三工具**如何串联**: 澄清流程(分批)、执行顺序、能力边界告知、安全红线 |
| 工具级 | `tool1-collect/SKILL.md` | smfetch 用法/坑 |
| 工具级 | `tool2-search/SKILL.md` | smsearch 用法/坑 |
| 工具级 | `tool3-analyze/SKILL.md` | smanalyze 用法/指标库/标注规范/坑 |

**设计决策**:
- 编排 skill 是**纯文档**(agent 读了照做), 不做可执行编排器 —— 工具保持独立可运行
- 路径**硬编码**在 skill 中(当前为单机单工程场景)
- 澄清**分批**进行(先采集范围 → 再变量 → 再标注标签), 不一次抛多个问题
- **工具不内置"自然语言→配置"能力**(agent 即 LLM, 重复劳动且引入不可控层; 见 tool3 DESIGN §10)

**典型编排流程**:
```
研究文档 → [澄清] 账号/范围 → [澄清] 变量清单(对照 smanalyze metrics)
        → [澄清] 标注标签体系 → [规划] 给用户确认
        → 工具2 搜索 → 工具1 采集 → 工具3 加工 → [交付] 变量表+诚实报告
```
